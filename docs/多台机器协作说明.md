# 多台机器协作说明

项目仓库：`https://github.com/wjarchy/FC-SFT-verifiedClassKD`。本文件只说明代码、数据和训练产物如何在不同机器间安全同步。

## 推荐分工

| 机器 | 适合的工作 |
|---|---|
| 个人电脑 | GitHub 推送、文档和代码修改、Hugging Face 登录、轻量数据处理 |
| 公司电脑 | 内网允许时拉取代码、离线改代码、运行自动测试；若推送被拦截则使用 Git bundle |
| AutoDL 或实验室 GPU | 模型下载、训练、候选打分和正式评测 |

机器分工不是实验定义。只要环境、数据、配置、代码版本和随机种子相同，GPU 工作可以迁移。

## 哪些内容如何同步

| 内容 | 同步方式 | 是否进入 Git |
|---|---|---|
| 源码、配置、测试、中文报告 | GitHub | 是 |
| `data/processed/`、`data/splits/` | 合规云盘、U 盘或在目标机器严格重建 | 否 |
| 候选池和 Teacher Scores | 合规云盘或实验机器本地 | 否 |
| 模型权重和 `outputs/` | 实验机器或大文件存储 | 否 |
| 访问令牌、`.env`、SSH 私钥 | 不同步或用安全凭据工具 | 绝不进入 Git |

大文件迁移后要核对 `manifest.json` 或相应报告中的 SHA256，不能只比较文件名。

## GitHub 正常可用时

首次获取：

```bash
git clone git@github.com:wjarchy/FC-SFT-verifiedClassKD.git
cd FC-SFT-verifiedClassKD
```

日常同步：

```bash
git pull origin main
git add <本次修改的文件>
git commit -m "简明说明"
git push origin main
```

提交前检查 `git status`，不要把数据、权重、令牌或无关修改一并提交。

## 公司网络无法推送时

公司电脑可以生成离线 Git bundle：

```bash
git bundle create fc_class_kd-update.bundle main
```

把该文件带到能访问 GitHub 的个人电脑，再恢复并推送：

```bash
git clone /path/to/fc_class_kd-update.bundle -b main fc_class_kd
cd fc_class_kd
git remote set-url origin git@github.com:wjarchy/FC-SFT-verifiedClassKD.git
git push -u origin main
```

bundle 只包含已经提交到 Git 的内容，不包含被 `.gitignore` 排除的数据和模型。

## 保证数据完全一致

最稳妥的方法是复制以下文件并核对 SHA256：

```text
data/processed/all_records.jsonl
data/processed/manifest.json
data/splits/*.jsonl
```

如果必须重建，需使用相同的数据源版本、代码版本、筛选参数和随机种子：

```bash
.venv/bin/python scripts/build_data.py --sources toolace --seed 42
```

只要数据源或筛选代码变化，就必须视为新数据版本并整体重新划分。不能声称与旧划分完全一致。

## AutoDL 网络铁律

`127.0.0.1:17890` 只供 OpenAI/Codex。任何其他 Shell 网络请求必须在单条命令中先清除代理。Hugging Face 或 GitHub 下载优先使用 AutoDL 临时学术加速，例如：

```bash
unset HTTP_PROXY HTTPS_PROXY ALL_PROXY http_proxy https_proxy all_proxy
source /etc/network_turbo >/dev/null
HF_HOME=/root/autodl-tmp/hf_cache <下载命令>
```

只修改当前命令的环境，不覆盖全局代理配置。模型和数据缓存放在 `/root/autodl-tmp`，避免占满系统盘。

pip install -e ".[dev]"
python scripts/doctor.py
