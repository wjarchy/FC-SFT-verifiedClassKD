# ToolACE 数据修复与 2,103 条筛选说明

## 一句话结论

cleaned ToolACE 的对话内容仍可用，但工具参数说明中的“是否必填”和“默认值”已经失真。项目因此从固定版本的原始 Team-ACE 恢复这些信息，只保留能够唯一、严格对齐且标准答案合法的样本，最终得到 2,103 条高置信数据。

## 丢失 `required` 和 `default` 会造成什么影响

`required` 表示参数是否必须出现。`default` 表示某个可选参数被省略时，工具是否有明确的替代值。两者决定一个函数调用是正确、等价正确还是参数错误。

cleaned 数据共有 24,223 个参数：

- 标为必填的参数是 0 个，意味着所有参数看起来都可以省略。
- 24,195 个参数带有默认值，占 99.88%。
- 21,145 个默认值是空字符串，占 87.29%。
- 其中很多整数、浮点数和布尔参数也被错误写成空字符串默认值。

这会产生四类直接影响：

1. 无法可靠制造 `missing_required` 错误。因为 cleaned 数据认为没有必填参数，删除任何参数都不算“缺少必填项”。
2. 验证器会把实际缺参数的调用误判为正确，从而虚高 AST 和正确类准确率。
3. 默认值等价关系会被污染。例如一个整数参数被写成 `default=""` 后，省略它可能被错误地当作与传入空字符串等价。
4. 候选池类别组成会失真。Wrong Arguments 数量、正确等价候选数量以及 Class KD 的教师类别概率都会随之错误。

因此，cleaned 参数说明下的“Gold 自检 100%”只能说明代码与这份有损说明内部一致，不能证明判断符合原始工具定义。

## 这个问题是谁造成的

结论分成两层：

1. 字段失真来自上游 cleaned 数据。我们直接检查了固定版本的原始 Parquet：例如 `float` 类型的 `lat`、`lng` 参数在文件里已经带有 `default=""`，工具也没有原始 JSON Schema 的 `required` 列表。本项目适配器只是把这些现有字段读入，没有主动删除 `required`，也没有生成空字符串默认值。
2. 旧版项目接入流程有责任。虽然字段不是我们清洗脚本改坏的，但旧流程没有先验证参数说明质量，就把 cleaned schema 当作验证器依据。这属于本项目的数据接入设计缺陷。

当前已经从两个方向修正：一是恢复原始 Team-ACE 参数说明；二是正式加载器在没有指定原始 Team-ACE 固定版本时直接报错，并增加回归测试，防止以后静默退回有损 schema。

## 如何恢复原始参数说明

使用的数据版本：

- cleaned：`tryumanshow/ToolACE-Qwen-cleaned`，版本 `74befe8a...`。
- 原始：`Team-ACE/ToolACE`，版本 `6bda777c...`。

恢复步骤如下：

1. 从 cleaned 数据读取已经整理好的单用户、单工具调用样本。
2. 解析原始 Team-ACE 每条数据 `system` 字段中的工具 JSON。
3. 用完全相同的用户问题查找原始样本，而且该问题必须只对应一个原始样本。
4. 继续核对工具数量与顺序、工具说明、每个工具的参数名集合。任何一项不同都不合并。
5. 保留 cleaned 数据中的函数名和调用文本；从原始数据复制参数类型、是否必填、可选值和真实默认值。
6. 用恢复后的工具说明重新验证标准答案。标准答案缺少必填参数或不符合类型时，整条剔除。

这里没有使用模糊文本匹配，也没有按两份数据的行号强行合并。

恢复后的 2,103 条数据共有 8,732 个工具、18,727 个参数。其中：

- 10,777 个参数是必填参数，占 57.55%。
- 3,286 个参数有明确默认值，占 17.55%。
- 300 个参数有明确的可选值集合，占 1.60%。

这个分布比 cleaned 数据中“全部非必填、几乎全部有默认值”更符合正常工具定义。

## 2,103 条数据是怎样筛出来的

筛选过程按固定顺序进行：

| 阶段 | 数量 | 说明 |
|---|---:|---|
| cleaned 原始行数 | 10,547 | 下载到的 cleaned 数据总量 |
| 满足单用户、单调用、参数可解析且至少有两个工具 | 2,947 | 7,600 条在读取和基础结构检查时剔除 |
| 通过 cleaned 阶段的内容过滤 | 2,690 | 再剔除 257 条 |
| 找不到完全相同的原始问题 | 17 | 剔除 |
| 同一个问题对应多个原始样本 | 11 | 无法唯一判断，剔除 |
| 唯一问题匹配且工具结构完全一致 | 2,662 | 成功恢复原始参数说明 |
| 恢复后标准答案不合法 | 559 | 全部属于缺少原始必填参数，剔除 |
| 最终高置信数据 | **2,103** | 全部保留，并与 xLAM 合并用于当前快速试验 |

最后 559 条不是因为代码解析失败，而是 cleaned 标准答案在原始参数说明下确实缺少必填参数。例如有的调用缺少 `campaign_id`，有的缺少 `make` 和 `year`，还有的缺少 `limit` 和 `page`。继续保留它们会让标准答案本身成为错误标签。

“高置信”表示这些数据通过了上述可复查条件，不表示原始公开数据绝对没有噪声。
