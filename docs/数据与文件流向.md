# V5 数据与文件流向

所有 V5 新产物必须放在带 `v5` 的目录或清单下，避免覆盖 V4 的混合数据、S0、K=6 草稿和人工标注记录。以下路径是后续实现约定；标为“计划”的文件目前尚未生成。

## 总体流向

```text
一个主 FC 数据源
  ↓ adapter + 质量筛选 + BFCL 去重
data/processed/v5/
  ├── all_records.jsonl
  └── manifest.json
  ↓ seed=42，一次性划分
data/splits/v5/
  ├── train.jsonl                 1500，S0 与正式训练
  ├── val.jsonl                    200，只用于选模
  ├── internal_test.jsonl          400，最终内部/自然等价 held-out
  └── opportunity_probe.jsonl      300，只用于机会 Gate

opportunity_probe
  ↓ Qwen3-8B 每条自然采样 8 次
data/candidates/v5/opportunity/teacher_samples.jsonl
  ↓ surface dedup + validate + canonicalize
data/candidates/v5/opportunity/unique_candidates.jsonl
  ↓ Teacher 完整序列重打分
data/cache/v5/opportunity_teacher_scores.jsonl
  ↓
reports/opportunity_report.json/.csv + opportunity_examples.jsonl
  ↓ Opportunity Gate Pass

Tiny Overfit → V5 Train Gold → outputs/v5/s0/
  ↓ 自然 candidate support + Gold + S0 hard error + distinct errors
  ↓ Gap Gate Pass
data/candidates/v5/train.jsonl + frozen_manifest.json
  ├── data/cache/v5/candidate_scores/
  └── data/cache/v5/token_fkl/
        ↓
outputs/v5/{sft_continuation,token_fkl,candidate_kd,class_kd}/
        ↓
Internal Test + held-out natural equivalence + BFCL
        ↓
reports/results_main.csv + 最终中文报告
```

## 数据隔离

| 数据 | 唯一用途 | 禁止事项 |
|---|---|---|
| Train | S0、候选池、四分支训练 | 不用于最终结论 |
| Validation | 训练过程选模 | 不报告为最终性能 |
| Opportunity Probe | 判断自然等价是否存在 | 不进入正式 KD 候选池或训练 |
| Internal Test | 最终内部生成与自然等价 held-out 发现 | 不调参、不选 checkpoint |
| BFCL subset | 外部有效性 guardrail | 不训练、不构造候选、不调参 |

Natural-equivalence held-out set 从完全封闭的 Internal Test 上使用相同自然采样流程发现，不强行凑到固定数量。≥30 条可作 Pilot 机制诊断，20–29 条只作弱证据，<20 条不作强结论。

## Candidate 记录

每个 V5 candidate 至少保存：

```text
query_id
candidate_id
raw_surface
parsed_call
validity
canonical_signature
source_tag
analysis_tag
```

- `source_tag` 可为 gold、teacher_sample、student_hard_error、wrong_function_rule、wrong_argument_rule。
- `analysis_tag` 只用于解释错误，绝不参与 class aggregation。
- invalid candidate 使用 `INVALID::<candidate_unique_id>` singleton signature。
- 正式 Train 每条 3–6 个候选；不存在自然 equivalent 时不人工补齐。

## Teacher cache

Candidate/Class cache 必须记录 raw log-prob sum、sequence length、length-normalized score、candidate probability、canonical signature、class probability、Teacher revision、tokenizer hash 和 prompt hash。

Token FKL cache 与 Candidate cache 分开保存，固定 top-k=100；STAR 的 exact prefix/trajectory construction 锁定前不得生成“正式复现”缓存。

## 报告输出

Data Opportunity Report 固定输出：

- `reports/opportunity_report.json`
- `reports/opportunity_report.csv`
- `reports/opportunity_examples.jsonl`

最终主表为 `results_main.csv`，四行分别是 SFT Continuation、Token KD/FKL、Candidate KD、Equivalence-Class KD；四种方法都计算 held-out Candidate/Inter/Intra KL。

## V4 历史路径

现有 `data/processed/manifest.json`、`data/splits/*.jsonl`、`data/candidates/*unfrozen.jsonl`、V4 S0 和 `Verifier人工标注表.xlsx` 均保留，不覆盖、不删除。它们记录旧方案事实，但不作为 V5 Gate 或正式训练输入，除非后续逐项证明与 V5 定义完全一致并形成新 manifest。

多机器同步与哈希核对见 `docs/多台机器协作说明.md`。
