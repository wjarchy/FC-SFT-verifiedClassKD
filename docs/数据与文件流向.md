# 数据与文件流向

所有路径相对于项目根目录。数据划分只做一次；Train、Validation、Diagnostic 和最终测试集合不能互相混用。

## 总体流向

```text
公开数据
  ↓ scripts/build_data.py
data/processed/all_records.jsonl         高置信全集
  ↓ 固定随机种子 42，一次性划分
data/splits/
  ├── train.jsonl                        训练 S0 和构造训练候选池
  ├── val.jsonl                          选择训练轮次
  ├── diagnostic.jsonl                   实验前诊断，不训练
  ├── internal_test.jsonl                最终内部评测
  └── equivalence_diagnostic.jsonl       最终等价性评测

Train Gold → outputs/s0_qwen3_1.7b_seed42/       公共 S0
  ├── S0 对 Train 生成 → s0_train_predictions.jsonl
  └── S0 对 Diagnostic 生成 → s0_diagnostic_predictions.jsonl
        ↓ 加入规则候选并自动检查
      train_unfrozen.jsonl / diagnostic_unfrozen.jsonl

未冻结候选池 → 人工审核 → train.jsonl / diagnostic.jsonl + 冻结哈希
  ├── Diagnostic 候选 → Teacher 与 S0 的 Pre-Diagnostic
  └── Train 候选 → data/cache/teacher_scores/ → 三条训练分支

三条分支 → Internal Test / Equiv Diagnostic / BFCL 自由生成评测
```

## 当前固定数据

当前正式全集 3,250 条，由 2,103 条 ToolACE 和 1,147 条 xLAM 组成。全部数据只进入一个划分。

| 文件 | 数量 | 唯一用途 |
|---|---:|---|
| `data/splits/train.jsonl` | 2,000 | 训练 S0、构造 Train 候选池、三条分支训练 |
| `data/splits/val.jsonl` | 300 | 选择训练轮次，不作最终结论 |
| `data/splits/diagnostic.jsonl` | 250 | 比较 Teacher 与 S0，不能用于训练 |
| `data/splits/internal_test.jsonl` | 500 | 最终内部评测 |
| `data/splits/equivalence_diagnostic.jsonl` | 200 | 最终等价性评测 |

ToolACE 与 xLAM 筛选细节分别见 `docs/ToolACE数据修复与筛选说明.md` 和 `docs/xLAM数据筛选说明.md`。版本、构建参数和 SHA256 见 `data/processed/manifest.json`。

## 各目录用途

### `data/processed/`

- `all_records.jsonl`：固定后的 3,250 条正式全集。
- `manifest.json`：数据源版本、构建参数、划分数量和文件哈希，是复查数据的主要依据。

### `data/splits/`

保存一次性固定划分。任何扩大或替换数据源都会使旧划分失效，必须整体重建并重新记录哈希，不能只给 Train 追加数据。

### `data/diagnostics/`

保存诊断衍生文件，例如初步验证器盲标包和等价变体。这里的文件不是训练主数据。

### `data/candidates/`

保存 S0 推理、候选池草稿和人工审核后的冻结候选池：

- `s0_train_predictions.jsonl`：S0 在 Train 上的自由生成与真实错误。
- `s0_diagnostic_predictions.jsonl`：S0 在 Diagnostic 上的自由生成与真实错误。
- `train_unfrozen.jsonl`、`diagnostic_unfrozen.jsonl`：严格 K=6、已自动检查但尚未人工审核的草稿。
- `train.jsonl`：人工审核通过后冻结，用于 Teacher Scores 和蒸馏训练。
- `diagnostic.jsonl`：人工审核通过后冻结，只用于判断 Teacher 是否强于 S0。

每条保存六个候选的原始文本、解析结果、验证器类别和候选来源。文件名含 `unfrozen` 或清单中
`frozen=false` 的文件禁止用于 Teacher 完整缓存和蒸馏训练。

### `data/cache/`

计划保存冻结候选的教师分数。主要文件为 `teacher_scores/train.parquet` 或等价 JSONL。必须同时记录模型、温度、提示格式、候选池哈希和逐候选分数。

### `outputs/`

保存模型权重和训练过程产物，不提交到 Git。计划目录包括：

- `outputs/s0/`
- `outputs/sft_continuation/`
- `outputs/candidate_kd/`
- `outputs/class_kd/`

### `reports/`

只保存体积小、便于人工查看的环境、诊断、训练和最终结果报告。逐样本预测放在被忽略的大文件目录，不把它们塞进 Markdown。

## 单条训练数据包含什么

- `query`：用户请求。
- `tools`：可选择的工具及参数说明。
- `gold_call`：标准函数调用。

候选和教师分数不写回固定数据划分，分别保存在 `data/candidates/` 和 `data/cache/`，避免混淆原始训练题与衍生信号。

## AST 指标的含义

本项目中的 AST 指模型输出能否解析成函数调用，并在验证器规范化后与标准答案结构等价。它不是要求输出字符串逐字相同：参数顺序不同、或按明确默认值省略可选参数，仍可能判为正确。

相关指标包括：

| 指标 | 含义 |
|---|---|
| Parse Success | 输出能否解析成规定格式 |
| Function Name Accuracy | 函数名是否正确 |
| Argument Accuracy | 参数结构和值是否正确 |
| AST | 整体调用是否与标准答案等价，主要指标 |
| Wrong Function / Wrong Arguments / Invalid | 错误分别落在哪一类 |

多台机器同步方式见 `docs/多台机器协作说明.md`。
