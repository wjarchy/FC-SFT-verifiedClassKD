# 公共 S0 训练说明

## 一句话定义

公共 S0 是 Qwen3-1.7B 在固定 Train 的标准答案上做普通 SFT 后得到的 LoRA。它只学习正确工具
调用，不读取候选池、验证器标签或 8B Teacher 分数。后续 SFT-cont、Candidate KD 和 Class KD
都必须从完全相同的 S0 开始。

训练入口为 `scripts/train_sft.py`，RTX 3090 参数位于 `configs/rtx3090.yaml`。

## 具体读取哪些数据

正式训练只读取两份已经冻结的文件：

| 文件 | 数量 | 来源组成 | 用途 | SHA256 |
|---|---:|---|---|---|
| `data/splits/train.jsonl` | 2,000 | ToolACE 1,279；xLAM 721 | 计算梯度 | `2f4353932c9c0da0397d88419bed71859fdd46383768b327e2693cca28dfd49a` |
| `data/splits/val.jsonl` | 300 | ToolACE 192；xLAM 108 | 选择 S0 轮次 | `a0e32d497ae8d4e0afe6876412dac82eb8ab151b319f6eaf3dc4dd08d4948e63` |

这两份文件的上游是 `data/processed/all_records.jsonl`，版本和构建过程由
`data/processed/manifest.json` 固定。训练脚本不会重新下载或重新清洗数据。

以下数据此时完全不读取：

- `internal_test.jsonl`：只用于最终内部评测。
- `diagnostic.jsonl`：等 S0 完成后比较 Teacher 与 S0。
- `equivalence_diagnostic.jsonl`：只用于最终等价性评测。
- BFCL：只用于最终外部评测。

## 一条 Train 数据怎样变成训练样本

第一条真实数据位于 `data/splits/train.jsonl` 第一行：

```text
ID：toolace_3082
来源：ToolACE
候选工具数：6
```

用户问题是：

```text
我想了解西班牙自治区的省级结构，先查询自治区 ID “12”。
```

六个工具中既有正确工具 `Provinces by Autonomous Community`，也有地形瓦片、地址补全、
高度图、余额查询和路线规划等干扰工具。标准答案是：

```json
{
  "name": "Provinces by Autonomous Community",
  "arguments": {"id_comunidad": "12"}
}
```

Qwen3 实际看到的是：六个完整工具说明、用户问题和 assistant 起始标记。需要学习的输出是：

```text
<tool_call>
{"name": "Provinces by Autonomous Community", "arguments": {"id_comunidad": "12"}}
</tool_call>
```

这条样本完整长度为 1,580 token，其中只有最后 27 个 assistant 工具调用 token 计算 SFT loss；
工具说明和用户问题的标签全部是 `-100`，只作为条件，不要求模型复述。这样训练的是“看到工具和
问题后生成正确调用”，而不是背诵用户问题。

## 正式训练参数

| 项目 | 当前值 | 原因 |
|---|---:|---|
| 基础模型 | Qwen3-1.7B 固定版本 `70d244cc...` | 与 v4 的主 Student 一致 |
| 训练方式 | 4-bit NF4 QLoRA | 3090 24GB 可稳定运行，并保留固定基础模型 |
| LoRA | r=16，alpha=32，dropout=0.05 | 已通过 0.6B/1.7B 冒烟和过拟合检查 |
| 最大长度 | 2,048 | Train 最长 1,707；Validation 最长 1,965，不允许截断 |
| 训练轮数 | 3 | 2,000 条数据较小，保留三个可比较轮次，不默认最后一轮最好 |
| 微批次 | 1 | 控制 24GB 显存峰值 |
| 梯度累计 | 16 | 等效批量为 16，降低单样本梯度波动 |
| 优化器 | AdamW | 只更新 LoRA 参数 |
| 学习率 | `2e-4` | QLoRA 的保守起点；不使用过拟合检查中的 `5e-4` |
| 学习率变化 | 3% warmup 后余弦下降 | 避免开始阶段突变，并平滑收尾 |
| 梯度裁剪 | 1.0 | 防止偶发大梯度破坏检查点 |
| 随机种子 | 42 | 固定每轮数据顺序和模型随机状态 |
| 优化次数 | 每轮 125，共 375 | 2,000 / 16，三轮固定预算 |

每个梯度累计组按实际 assistant token 数加权。长、短工具调用不会因为碰巧落在不同微批次而
获得不合理权重。

## 如何选择最终 S0

每一轮结束后执行两种 Validation 检查：

1. 计算全部 300 条的 assistant-only Validation loss。
2. 用该轮检查点对同一 300 条自由生成，计算 AST、解析率、函数名和参数正确率。

最终首先选择 Validation AST 最高的轮次；如果 AST 相同，选择 Validation loss 更低的轮次；
如果仍然相同，选择更早的轮次。这样选择依据与 Function Calling 的主要目标一致，同时避免
用 Internal Test、Diagnostic 或 BFCL 调参。

## 断点与输出

默认输出目录为 `outputs/s0_qwen3_1.7b_seed42/`。主要文件为：

```text
run_manifest.json                  数据、模型、配置和代码状态
checkpoint-step-000000/            训练开始前的可恢复状态
checkpoint-step-000025/ ...        每 25 个优化器步骤保存
checkpoint-step-000125/            第一轮结束
checkpoint-step-000250/            第二轮结束
checkpoint-step-000375/            第三轮结束
latest_checkpoint.json             最近可恢复位置
best_loss_checkpoint.json          仅按 loss 的参考检查点
validation_by_checkpoint/          三个轮次的自由生成结果
selected_s0.json                   正式选模依据和三轮比较
best_checkpoint.json               最终公共 S0 指针
training_curve.json                去除断点重放重复项后的训练曲线
training_summary.json              训练与选模汇总
```

每个完整检查点保存 LoRA、AdamW、学习率调度器、CPU/CUDA 随机状态以及下一组数据位置。服务器
中断后，重新运行相同命令会从 `latest_checkpoint.json` 恢复。Validation 自由生成也是逐条落盘，
中断后不会重做已经完成的样本。

## 执行命令

只检查数据、长度和训练预算，不加载模型训练：

```bash
HF_HOME=/root/autodl-tmp/hf_cache \
.venv/bin/python scripts/train_sft.py --config rtx3090 --prepare-only
```

正式训练或断点续训使用同一条命令：

```bash
HF_HOME=/root/autodl-tmp/hf_cache \
.venv/bin/python scripts/train_sft.py --config rtx3090 --resume auto
```

脚本默认只接受本地模型目录，因此这两条命令不会下载模型，也不会使用
`127.0.0.1:17890`。`--max-train-samples` 和 `--max-val-samples` 只允许工程调试；使用后输出会明确
标为非正式运行，不能作为 S0。
