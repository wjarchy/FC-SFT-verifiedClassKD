# 验证器人工审核说明

> **V4 历史流程。** 本文和 `data/diagnostics/Verifier人工标注表.xlsx` 检查的是旧方案的
> correctness/error taxonomy。V5 已禁止用四类错误标签定义 KD class，因此这份审核不能替代
> V5 的 deterministic canonicalizer 14 类测试与审计，也不能据此冻结 V5 候选池。

目标是用独立人工判断检查验证器是否能可靠地把候选调用分到四个主类。不要根据候选的生成方式猜标签；只阅读用户问题、可用工具、标准答案和待判断候选。

## 标签含义

- `correct`：函数、参数结构和值都正确。只存在参数顺序变化、明确默认值的省略或项目允许的规范化差异时，也归为正确。
- `wrong_function`：调用了错误函数，或函数名不在给定工具列表中。
- `wrong_arguments`：函数正确，但参数缺失，或参数名、类型、可选值、具体值错误，或出现工具说明不允许的参数。
- `invalid`：无法解析成项目要求的单个 `{name, arguments}` 调用。
- `unknown`：只有在工具说明不足、依赖外部知识或运行时状态，人工也无法高置信判断时才使用。

`wrong_arguments` 可以补充子标签：缺少必填参数 `missing_required`、错误参数名 `wrong_key`、错误类型 `wrong_type`、错误参数值 `wrong_value`。

## 标注步骤

推荐直接填写 Excel，不需要修改 JSONL：

1. 打开 `data/diagnostics/Verifier人工标注表.xlsx`。
2. 先阅读“标注说明”工作表，再进入“人工标注”工作表。
3. 每行只填写绿色的三列：`人工标签（必填）`、`参数错误细分（可选）`、`备注`。
4. `人工标签` 和 `参数错误细分` 都有下拉菜单；表格顶部会自动显示已填写数量，可以随时保存后继续。
5. 全部填写完成后告诉 Codex“Excel 已标完”。Codex 会先做完整性检查，再导回正式盲审包并计算审核结果。

表格生成和导回命令如下，通常由 Codex 执行：

```bash
.venv/bin/python scripts/生成Verifier人工标注Excel.py
.venv/bin/python scripts/导入Verifier人工标注Excel.py --check-only
.venv/bin/python scripts/导入Verifier人工标注Excel.py
```

原来的终端逐条标注工具仍然保留作为备用方式：

```bash
.venv/bin/python scripts/annotate_verifier_audit.py
```

无论使用哪种方式，都不要运行验证器，也不要查看隐藏的预测或候选来源。无法确定时选择“无法确定”或填 `unknown`，并在备注中说明缺少什么信息，不要强行猜测。

导回全部人工标签后运行：

```bash
.venv/bin/python scripts/score_verifier_audit.py
```

只有输出报告显示两个门槛都通过，才运行：

```bash
.venv/bin/python scripts/freeze_candidate_pools.py
```

该命令会再次核对人工审核所绑定的两个草稿哈希，再生成 `data/candidates/train.jsonl`、
`diagnostic.jsonl` 和 `frozen_manifest.json`。审核失败或草稿发生变化时会直接停止。

## 通过条件

- 在验证器判为正确或等价的候选中，人工确认确实正确的比例至少为 98%，即正确类精确率至少为 98%。
- 四个主类的整体分类准确率至少为 95%。

正式包由 `scripts/prepare_verifier_audit.py` 从 Train 与 Diagnostic 的完整未冻结 K=6 候选池生成，默认共 200 条：四个验证器主类各 40 条，另单独抽取 40 条 S0 真实错误。可见标注包不含验证器预测、候选来源或抽样层；这些信息单独保存在 `verifier_human_audit_final_key.jsonl`，标注完成前不要打开。

旧的 `verifier_human_audit.jsonl` 是 S0 训练前的规则候选包，只能作为历史检查，不能代替正式审核。正式审核通过后，才能冻结候选池并进入教师缓存和蒸馏训练。
